# 回访提醒

一个原生微信小程序：在用户确认后调用 `wx.addPhoneCalendar`，把回访事件写入手机系统日历。项目没有后端、网络请求、登录、云开发或本地存储；表单内容只在当前页面内存中使用，添加成功后会清空。

## 产品边界与敏感信息

- 这是日历提醒工具，不提供诊断、治疗、在线问诊或医疗建议，也不应以医疗服务能力宣传。
- 只填写完成回访所需的最少信息，建议使用内部编号或不具识别性的简称。
- 不得填写身份证号、手机号、住址、诊断、完整姓名、完整病历等敏感信息。事件标题和备注会进入系统日历；日历数据可能受用户自己的系统同步、备份和共享设置影响。
- 小程序本身不上传或持久化表单数据，但无法控制用户设备及其日历服务对已添加事件的处理。

## 前置条件

- Node.js 与 npm（建议使用当前维护中的 LTS 版本）。
- 最新稳定版微信开发者工具。
- 已注册的小程序及有开发权限的微信账号；发布前完成主体、备案、类目、隐私保护指引等平台要求。
- 支持 `wx.addPhoneCalendar` 的微信与基础库（该接口最低基础库为 2.15.0；项目当前配置为 3.7.12）。

## 安装、测试与导入

```bash
npm install
npm test
npm run typecheck
npm ls --depth=0
```

1. 打开微信开发者工具，选择“导入项目”。
2. 项目目录选择本仓库根目录（包含 `project.config.json` 的 `follow-up-reminder` 目录）；工具会按 `miniprogramRoot` 使用 `miniprogram/`。
3. `project.config.json` 故意保留 `"appid": "touristappid"`。用真实账号调试时，在开发者工具“详情 → 基本信息”中修改 AppID；工具应将个人 AppID 写入优先级更高的 `project.private.config.json`。该文件已被 `.gitignore` 排除，请勿提交真实 AppID、密钥、上传私钥或其他凭据。
4. 若工具版本没有按上述方式保存，可在已忽略的 `project.private.config.json` 中设置 `"appid": "你的真实 AppID"`，仍不要修改并提交公共配置。
5. 编译后先用“预览/真机调试”验证，再考虑上传。

## 提交审核

1. 完成下面的真机清单和隐私、类目、备案等合规自查。
2. 在开发者工具中使用真实 AppID，点击“上传”，填写版本号和准确的项目备注。
3. 登录微信公众平台，在“版本管理 → 开发版本”找到上传版本；建议先设为体验版复核。
4. 点击“提交审核”，按实际页面填写功能页、类目、隐私和审核说明。审核说明应明确这是“用户主动将回访提醒写入系统日历的工具”，不要描述不存在的诊疗能力。
5. 审核通过后由有权限的管理员发布；被拒时按具体意见修正后重新上传、提审。

## 真机验收清单

开发者工具不能替代真机。至少覆盖：

- [ ] iPhone 一台。
- [ ] 至少两种不同厂商或系统版本的 Android 设备。
- [ ] 鸿蒙微信（如测试条件可用；官方接口文档标注支持鸿蒙 OS 版）。
- [ ] 首次调用时的日历/隐私授权：同意后能创建事件。
- [ ] 拒绝授权后，提示清楚且可进入设置；用户手动开启后返回重试成功。
- [ ] 默认 30 天以及跨月、跨年日期正确，提醒时间与本地时区正确。
- [ ] 中文标题和备注在系统日历中显示正常。
- [ ] 创建完成后断网，到期仍由系统日历触发提醒。
- [ ] 快速重复点击不会创建重复事件。
- [ ] 在系统日历中修改、删除事件可正常完成。
- [ ] 系统日历通知开关、省电/后台限制开启和关闭时的实际提醒表现已记录。

## 已知限制

- 小程序只能添加事件，不能修改或删除已经写入的事件；用户需在系统日历中操作。
- 实际通知是否出现、是否准时由系统日历、通知权限、省电策略和设备厂商行为决定，小程序无法保证。
- 开发者工具无法完整模拟系统授权、系统日历写入和通知，最终结论必须来自真机。
- 本仓库的自动化测试与类型检查不等于微信平台审核通过，也不验证真实 AppID、公众平台配置或真机通知链路。
